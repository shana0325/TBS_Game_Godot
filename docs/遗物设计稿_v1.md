# 遗物设计稿 v1 — 机制种子 · 混搭友好

> 关联：`data/relic/relics.json`（现有 5 遗物）、`docs/英雄联盟符文参考_LoL_Runes_v16.18.md`（对标来源）
> 状态：设计稿。数据示意可直接落进 `relics.json`；标注「需扩展」的触发/效果需在效果引擎补 token。

---

## 0. 设计定位：遗物 = 机制种子，不是流派开关

本稿核心态度一句话：**遗物给"释放某个行为后的有条件回报"，不给"你从此只能打 XX 流派"。**

- 触发维度绑在 **动作/事件** 上（攻击、施法、受击、击杀、回合开始），不绑在**流派标签**上（流血/护盾/反击/召唤）。
- 因此"攻击流""技能流""坦克流""混搭队伍"都能从同一批遗物里各取所需，专精一条路线不会因为某个遗物而碾压混搭。
- 遗物 vs 祝福分工：**祝福 = 数值**（全局 %，微调），**遗物 = 机制**（改变"发生的事"）。不让两者互相重叠占味道。

> 与符文的对照：LoL 基石符文偏"选一个定死主轴"（强攻/电刑/彗星），本稿刻意不抄这层，只借鉴它的**决策张力**（每拿一件像一次取舍）和**数值语言**（层数/阈值/冷却）。

---

## 1. 三条硬原则

1. **非专精**：遗物触发条件 = 行为而非流派标签；不出现"本局所有流血相关 +25%"这类绑定单线的收益。
2. **机制优于数值**：优先给"新交互/新反馈"，数值型遗物只作微调、且必须和祝福区分。
3. **数值纪律（红线）**：
   - `turn_interval` / 行动速度 ∈ **不升级区**，任何遗物/祝福不得把它做成成长项。
   - 同一效果的叠加设有收敛上限（见 §4 带宽表），防指数膨胀。

---

## 2. 分类框架：按"触发维度"分，不按"流派"分

| 维度 | 说明 | 代表触发 |
|---|---|---|
| **叠层反馈** | 持续做某事→叠层→满层给爆发/减免 | 造成伤害、治疗、受击 |
| **阈值处决** | 目标进入某个状态→额外回报 | 低生命、护盾归零、被控制 |
| **恢复引擎** | 击杀/溢出→回血回资源 | 击杀、治疗溢出、护盾击碎 |
| **冷却返还** | 施法/命中→返还技能冷却 | 施放主动技能、连击 |
| **护体周期** | 周期性豁免高伤（类骨甲镀层） | 时间节拍上的首次受击 |

每件遗物从**一个**维度取值，便于取舍与组合。

## 3. 遗物清单（第一版 8 件，覆盖 4 个维度）

### A. 叠层反馈

#### 3.1 动量符记 momentum_rune（传说 R3）
- **玩家描述**：造成伤害会叠层，每层伤害 +1%，至多 +15%；被击后叠层清空。
- **数据示意（需扩展）**：
  `triggers: [{ "event":"on_deal_damage", "stack":{"stat":"damage_mult","per_stack":0.01,"max":0.15,"reset_on":"own_take_hit"} }]`
- **设计意图**：奖励持续输出、惩罚挨打；物伤/法伤/连击都叠，不挑流派。
- **落地备注**：需效果引擎支持"叠层 stat + 被打重置"。

#### 3.2 战意坚盾 battle_tenacity（稀有 R2）
- **玩家描述**：连续承受伤害时叠层减伤，每层 -3%，至多 -15%；连续 3 秒未受击则清空。
- **数据示意（需扩展）**：
  `triggers:[{ "event":"on_take_hit", "stack":{"stat":"damage_reduction","per_stack":0.03,"max":0.15,"reset_after_idle":3.0} }]`
- **设计意图**：与 3.1 对称，奖励坦克抗线；任意前排通用。
- **落地备注**：需"脱离战斗计时重置"。

### B. 阈值处决

#### 3.3 绝命之印 executioner_mark（稀有 R2）
- **玩家描述**：目标生命低于该次伤害前的 **30%** 时，此次伤害提高 40%。
- **数据示意（可部分用现有 condition 思想，需扩展）**：
  `triggers:[{ "event":"on_attack", "condition":{"target_hp_percent":{"lt":0.3}}, "effects":[{"type":"damage_power_mult","mult":1.4}] }]`
- **设计意图**：斩杀手感，任何单位对残血敌都有收益 → 天然"补刀位"，不锁流派。
- **落地备注**：现有技能里已有 `target_hp_percent.lt` 条件（见 `Execute`），可复用条件语法；遗物侧补 `damage power` 倍率效果。

### C. 恢复引擎

#### 3.4 血契之环 life_chain（稀有 R2）
- **玩家描述**：任意单位击杀敌人时，全队恢复最大生命 3%。
- **数据示意（`on_kill` 已有，扩展为团队目标）**：
  `triggers:[{ "event":"on_kill", "heal_max_hp_percent":{"team":0.03} }]`
- **设计意图**：击杀→全队续航；与吸血/护盾组合不冲突，混搭友好。

#### 3.5 愈合余烬 overheal_ember（传说 R3）
- **玩家描述**：治疗溢出部分转化为伤害加成（上限 +20%）。
- **数据示意（需扩展）**：
  `triggers:[{ "event":"on_heal_overflow", "stack":{"stat":"damage_mult","per_overflow":1.0,"max_percent":0.20} }]`
- **设计意图**：奶妈向种子，让"治疗量多到溢出"也有回报；不与专精治疗绑定。
- **落地备注**：需引擎感知"治疗溢出量"并累计。

### D. 冷却返还

#### 3.6 回响法印 echos_pact（稀有 R2）
- **玩家描述**：每次施放主动技能，该技能剩余冷却缩短 25%。
- **数据示意（需扩展）**：
  `triggers:[{ "event":"on_cast_active_skill", "cd_reduce_percent":0.25 }]`
- **设计意图**：技能绝流程，任何带主动技能的构建通用；不做成"只有法术单位能用"。

#### 3.7 节奏火花 tempo_spark（普通 R1）
- **玩家描述**：战斗开始时，所有单位获得 15% 行动进度的先手优势。
- **数据示意（需扩展，注意不碰 turn_interval 成长）**：
  `triggers:[{ "event":"on_battle_start", "action_prefill_percent":0.15 }]`
- **设计意图**：先手价值，一次性（非成长）；刻意不落成"速度 +%"，守红线。

### E. 护体周期

#### 3.8 圣盾节律 aegis_rhythm（稀有 R2）
- **玩家描述**：每 8 秒，承受的第一次伤害降低 50%。
- **数据示意（需扩展）**：
  `triggers:[{ "event":"on_take_hit","interval":8.0,"first_hit_reduce":0.5 }]`
- **设计意图**：周期豁免（对标骨甲镀层"一次性/周期" 思路），任何站位通用。

## 4. 数值纪律与带宽（防指数膨胀）

| 生效频道 | 允许带宽 | 备注 |
|---|---|---|
| 伤害加成（全局叠层） | ≤ +20% | 3.1(15%)、3.5(20%) 上限封顶 |
| 减伤（叠层） | ≤ -20% | 3.2 封顶 -15% |
| 斩杀阈值倍率 | 单件 ≤ ×1.5 | 与技能"斩杀"同带宽，避免叠乘失控 |
| 治疗/回血(团队%) | ≤ 建议单件 ≤5% | 3.4 取 3% |
| 冷却返还 | 单件 ≤ -30% | 3.6 取 25% |
| 行动速度/turn_interval | **0** | 红线，不做 |
| 单件给自己定义的叠层上限 | stat 独立上限 | 每件 max 彼此独立，不叠加乘法 |

- 多件遗物**同类叠层**采用"各算各、取峰值或求和但封总上限"策略，设计与实现都倾向**加法再封顶**，避免互乘。
- 尚无"金币/商店"节点，故本稿暂不给金币类遗物，避免悬空（后续加商店再补）。

x 表示现有 `data/relic/relics.json` 已具备；需要补 token 的如下：

| 能力 | 用途 | 当前状态 |
|---|---|---|
| `on_kill` 触发 | 3.4 | 有（现有 `blood_pendant`） |
| `on_first_death` 触发 | —— | 有（`undying_emblem`） |
| `stat_percent` / `reflect` / `turn_speed` | 原 5 遗物 | 有 |
| **叠层 stat（按事件增减）** | 3.1 / 3.2 / 3.5 | 需扩展 |

| **团队目标恢复** | 3.4 | 需扩展 `heal` 目标加 `"team"` |

> 建议按"叠层 stat 框架"优先，因为它支撑 3.1/3.2/3.5 三件，且是未来机制型遗物最通用的地基。
