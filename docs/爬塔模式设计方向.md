# TBS_Game_Godot 爬塔模式设计方向（供 Codex / DeepSeek 开发参考）

> 当前实现状态：已落地层数推进、跨层阵容/位置保留、战斗场景内奖励悬浮窗、奖励选择后进入下一层、跳过奖励进入下一层、遗物/祝福基础系统。商店、事件和无限层仍属于规划内容。

## 文档目的

本文档不是具体实现方案，而是针对当前 TBS_Game_Godot 项目的玩法方向建议。

目标：

- 为现有自走棋战斗系统增加 Roguelike 爬塔模式；
- 充分利用现有技能触发系统与效果库；
- 避免陷入单纯数值膨胀；
- 提高局内构筑乐趣与重复游玩价值。

---

# 一、项目定位调整

当前项目已经不是传统自走棋。

更接近：

```text
Brave Nine（棕色尘埃）
+
Auto Battler
+
Roguelike 爬塔
```

现有系统已经具备：

- 自动战斗
- 时间驱动独立回合
- 技能触发系统
- Buff系统
- 装备系统
- 编成系统
- 永久成长系统

因此后续开发重点不应放在：

```text
等级提升
属性提升
数值膨胀
```

而应放在：

```text
构筑
技能联动
随机奖励
遗物系统
敌人机制成长
```

---

# 二、成长体系重构

建议将成长拆分为：

## 1. 局外成长（Meta Progression）

长期保留。

作用：

```text
长期养成
角色收集
降低新手门槛
```

包括：

```text
角色等级
属性点
技能学习
装备收集
永久强化
```

### 设计原则

局外成长幅度不要过大。

推荐：

```text
总战力成长控制在20%~30%
```

示例：

```text
初始：
100 HP
20 ATK

满培养：
130 HP
25 ATK
```

局外成长只提供：

```text
小优势
长期目标
```

不决定胜负。

---

## 2. 局内成长（Roguelike Core）

这是爬塔模式核心。

玩家每场重新构筑。

主要成长来源：

```text
随机技能
随机装备
遗物
祝福
临时强化
```

而不是经验升级。

---

# 三、爬塔奖励设计

## 普通层奖励

战斗结束后：

三选一

例如：

```text
攻击 +10%

生命 +20%

防御 +10%
```

或：

```text
获得随机装备

获得随机通用技能

获得随机属性强化
```

---

## 精英层奖励

三选一

例如：

```text
稀有装备

稀有技能

遗物
```

---

## Boss层奖励

固定获得：

```text
遗物
```

Boss层奖励应该明显强于普通奖励。

---

# 四、遗物系统（推荐优先开发）

遗物是爬塔模式核心。

特点：

```text
不占技能槽
永久持续到本局结束
可形成流派
```

示例：

### 战神徽章

```text
全体攻击 +15%
```

### 急速披风

```text
全体行动速度 +10%
```

### 鲜血吊坠

```text
击杀回复10%生命
```

### 不灭徽记

```text
首次死亡后复活一次
```

### 荆棘之心

```text
反伤 +30%
```

---

# 五、敌人成长设计

## 不建议

单纯：

```text
HP ×1.2
ATK ×1.2
```

这种设计会快速失去乐趣。

---

## 推荐

敌人成长主要来自：

```text
技能数量增加
技能组合增加
机制增加
```

而不是属性增加。

---

### 示例

第1层：

```text
普通哥布林

普通攻击
```

---

第5层：

```text
精英哥布林

普通攻击
反伤
```

---

第10层：

```text
哥布林王

普通攻击
反伤
死亡召唤
```

---

第15层：

```text
强化哥布林王

普通攻击
反伤
死亡召唤
击杀成长
```

---

这样即使属性只增长20%左右：

难度仍然会大幅提升。

---

# 六、利用现有技能系统进行内容扩展

当前项目已经拥有：

```text
14种触发时机
20种效果类型
```

这是项目最大优势。

后续开发重点：

```text
增加技能组合
增加Buff组合
增加敌人机制
增加遗物联动
```

而不是继续扩展基础属性。

---

## 技能联动示例

### 流血流

```text
攻击附加流血

攻击流血目标额外伤害

击杀流血目标回血
```

---

### 护盾流

```text
行动获得护盾

护盾存在时伤害提升

护盾破裂造成AOE
```

---

### 反击流

```text
受击反击

反击附加减速

反击击杀永久成长
```

---

### 召唤流

```text
死亡召唤

召唤物强化

召唤物死亡触发Buff
```


循环。

# 八、关于行动速度（turn_interval）

当前项目核心数值之一：

```text
turn_interval
```

其影响远高于普通攻击力。

例如：

```text
1.0秒行动一次
↓
0.8秒行动一次
```

实际输出提升：

```text
25%
```

因此：

## 设计原则

不要将 turn_interval 纳入常规成长体系。

不要出现：

```text
每层获得速度成长
无限叠加速度
```

否则容易产生指数级膨胀。

---

推荐：

```text
turn_interval 固定
```

仅允许：

```text
极少数遗物
极少数Boss机制
极少数特殊Buff
```

进行有限调整。

# 十、最终目标

玩家体验不应该是：

```text
我的角色从100攻击成长到500攻击
```

而应该是：

```text
这局我要玩什么流派？

流血流？

反击流？

护盾流？

召唤流？

这次拿哪个遗物？
```

构筑决策应成为游戏核心乐趣。

数值成长只负责支撑构筑，而不应成为主要内容。
